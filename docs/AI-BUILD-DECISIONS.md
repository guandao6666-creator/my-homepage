> 只记录**会影响后续实现**的决策：为什么这样做、为什么不那样做、代价是什么。
> 与代码注释互补：注释解释「这一行」，这里解释「这个方向」。

## D-001 · 旧版应用采用「元数据同步 + 实现异步」而非整体重写（2026-11-18）

- **背景**：入口 chunk 525,102 B，超出 Phase 6.1 的 450 KB 预算；16 个旧应用实现全部静态打包在入口。
- **选择**：新增 `src/lib/legacy-apps/manifest.ts` 保存 id/title/width/height/glyph + `load()`，
  `registerLegacyApps` 统一走外壳既有的 `load()` 通道（骨架屏 → 替换 → init）。
- **放弃的方案**：
  1. 把应用改成异步 `body()` —— 需要改 WindowManager 的同步挂载契约，违背「不重写窗口系统」。
  2. 每个应用再拆 meta/impl 两个文件 —— 16 个文件翻倍，收益相同而维护面更大。
  3. `manualChunks` 强行分包 —— 只是把同一个包切成两块同时加载，属指标游戏，不是真优化。
- **代价**：元数据在两处出现（清单 + 模块导出），已用单测「清单元数据与模块导出完全一致」锁定。
- **收益**：−42,163 B；首次打开应用多一次 chunk 请求（已被 12 秒超时与崩溃卡片兜底）。

## D-002 · 不硬拆 `os13.ts` 闭包（2026-11-18）

- **背景**：`os13.ts` 占入口 10.4%（2,397 行），是剩余体积最大单模块。
- **选择**：本轮不动。它把壁纸、桌面图标、Dock、控制中心、设置面板共用的 `cfg` 与 DOM 状态闭在一个 IIFE 里，
  拆任何一块都要把 10+ 个闭包函数改成显式传参。
- **理由**：纲领明确禁止「为了减少行数随意拆分代码」；这类拆分需要 Settings Service 作为落点，
  否则只是把闭包改成参数透传，可维护性不升反降。
- **后续**：等 Core Settings API（`docs/AI-BUILD-BACKLOG.md` P2-6）。

## D-003 · 性能预算以「原始字节」计（沿用 2.0 审计口径）

- **选择**：入口 JS 与首屏 CSS 的预算按未压缩字节统计（与 `GUANDAO_2_0_AUDIT.md` §10.1 的 497 KB / 267 KB 同口径）。
- **理由**：gzip 后体积受内容重复度影响，不能反映解析与执行成本；换口径会让历史数据不可比。
- **代价**：数字看起来比「传输体积」大，需要在报告里同时给出 gzip 值以免误读。

## D-004 · 环境性失败与代码性失败必须分开记录

- **背景**：本机沙箱的 safe-delete 守卫会在 Astro 清理 `dist/.prerender`、Playwright 清理 `test-results` 时中断进程。
- **选择**：这类失败不计入工程质量结论，但必须在 STATUS 与 LOG 中写明规避方式与复现条件。
- **理由**：把环境问题当成代码失败会误导下一轮；反过来把失败掩盖成通过则违反「No Fake Features」。

## D-006 · 预算指标必须由脚本测量，不能按「最像的那个文件」计（2026-11-18）

- **背景**：6.2 把应用样式从首屏样式表搬到懒加载模块后，最大单文件从 273,238 B 降到 196,151 B，
  看起来达标；但解析首页 HTML 后发现 Astro 仍把 18 个异步 chunk 的 CSS 以 `<link>` 注入首页，
  实际首屏 CSS 为 463,013 B。
- **事实**：Astro 静态构建会把「页面可达的所有 CSS」提升为首页样式表链接，用于避免 FOUC；
  动态 import 的 CSS 不会自动延后到 chunk 加载时。
- **决策**：
  1. 「首屏 CSS」的口径固定为**首页 `<link rel="stylesheet">` 总和**，由 `scripts/perf-baseline.mjs` 计算并作为门禁；
  2. 单文件体积只作辅助信息，不作验收依据；
  3. 后续若要做真正的延迟加载，只能把 CSS 当资源（`?url`）在运行时插 `<link>`，并在 `load()` 中等待，
     不能依赖「把 import 挪进懒模块」。
- **代价**：每次涉及样式的改动都要重跑 `perf:baseline`；预算不达标时门禁会失败。
- **教训**：先用脚本定义指标，再改代码。否则容易用相关但不等价的数字确认自己。

## D-005 · 项目记忆文件复用现有文档，不另起一套

- **选择**：`AI-BUILD-STATUS/BACKLOG/DECISIONS/LOG` 只记「当前状态 / 待办 / 决策 / 每轮记录」，
  架构细节仍写在 `docs/architecture/*`，验收与发布记录仍写在 `ACCEPTANCE-2.0.md` / `RELEASE-2.0.md`。
- **理由**：纲领要求「如果已有等价文件，优先复用，不创建重复文档」。
