## 1. 这轮踩过的坑

1. **非 UUID 的测试 id 会在校验层被提前拦掉**
   给「审核员通过 draft」写行为用例时，我用了 `post-draft` 这种可读 id，
   `adminReviewPost` 第一行就是 `UUID.test(id)`，直接 404，断言看到的是「作品不存在」
   而不是「作者已撤回」。换成一个真 UUID（`b7d0c3d2-…`）后才打到状态策略。
   → 调 `/admin/**` 的用例，id 一律用 UUID；否则你测的是校验层，不是你要测的分支。

2. **状态机测试要与真实入口串联**
   只测纯函数 `checkReviewTransition` 很容易「矩阵全绿但接线错了」。
   本轮额外加了一条真的调 `adminReviewPost` 的行为用例，并用源码断言锁住
   「UI 按钮文案 ↔ 服务端放行状态」的对应关系。

3. **负向对照要能报出「旧文案」**
   还原 `admin.js` 后，失败信息是 `expected ApiError: 作品还没有可安装的内容包…`，
   这比「1 failed」本身更能证明对照命中了预期分支。
   → 负向对照跑完，把**实际收到的旧消息**贴进发布说明。

4. **逻辑删除的「复活」是第二类 bug**
   `deletePost` 只改 post/package/asset 三张表，举报表不动；
   而 `hide_post` 又把 `status` 无条件写成 `hidden`。两条单独看都「正常」，
   合起来才让已删作品重新出现。审计时要顺着**状态跨表传播**查，而不是只看单函数。

5. **`package-lock.json` 里出现 2.0.N 不一定是自己的版本**
   第 5097 行的 `"version": "2.0.6"` 是 `fast-levenshtein@2.0.6` 的依赖版本。
   → 只替换第 3、9 行；替换前先按行号定位，不要用全局 split/join。

## 2. 可复制任务书

> 给 Guandao OS 做补丁版本 2.0.8。先跑 `git status` 与 `node scripts/check-version.mjs`
> 确认起点干净；再看 `docs/AI-BUILD-STATUS.md` §5 风险表与 `docs/RELEASE-2.0.7.md` §6。
>
> 范围：优先处理不需要数据库迁移、不改公开响应字段的缺陷；需要迁移的（计数幂等、
> 社区上传配额预占）单独列清单，不要塞进补丁版。
>
> 硬约束：
> 1. 每条修复必须有「失败复现 → 修复 → 通过」的证据；负向对照必须真的把代码改回旧行为跑一次。
> 2. 界面链路用真实 Worker 的 Playwright（`--project=worker`），断言「点下去 → 界面到哪」，
>    不许用 mock 冒充端到端；纯函数才用单测。
> 3. 不改公开 API 契约；若必须改，同步文档 + 测试，并在发布说明里单列「行为变更」。
> 4. 不加数据库迁移。
> 5. 版本号 9 处同步，`package-lock.json` 只改第 3、9 行（第 5097 行是依赖版本）。
> 6. 既有断言不许删；版本号出现在测试/脚本/CI 里就一起更新，并在提交说明里写为什么。
> 7. 临时脚本的默认动作必须是「拒绝执行」，恢复后校验 SHA256。
> 8. 一次最多两个子智能体；必须等到收尾消息才算拿到结论，只看到 inactive 不算。
> 9. 中文注释写「为什么」，不留调试插桩；失败现场截图存档。
>
> 验收：`npm run verify` 全绿（任一项红都不算完成）+ 全量 E2E 全绿；
> 发布说明区分 Implemented 与 Verified，未部署就写 Blocked。
>
> 交付：`docs/RELEASE-2.0.8.md`、`docs/PROMPT-2.0.8.md`、BACKLOG 追加 Round、
> STATUS 更新（版本/单测数/E2E 数/体积）、LOG 追加一条。

## 3. 对照表

| 说你要什么 | 实际要做 |
| --- | --- |
| 「继续修」 | 先看上一版发布说明的 §6，再查 STATUS 风险表，别重新扫全仓 |
| 「一次只能两个子智能体」 | 派单 → 等收尾消息 → 派下一批；inactive 不等于完成 |
| 「给证据」 | 失败时的真实输出 + 修复后通过 + 负向对照，三件套缺一不可 |
